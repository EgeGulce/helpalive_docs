<Note>
  **Optional, and recommended for security.** HelpAlive works fully without this step. Without it, HelpAlive trusts the user id your page sends, so someone who edits the page in their browser could send another person's id and read that person's chats. With it, your server signs each id, and once you turn on **Only allow verified users**, nobody can pretend to be someone else. Add it before you open the agent to all your users.
</Note>

Your developer, about 15 minutes. You'll find everything below, with your own secret, on **Settings → Setup & API Key**, step 4.

## 1. Your signing secret

Click **Create your signing secret** on the setup page. Keep it on your server, like a password, wherever you keep other secrets. The code below reads it from `HELPALIVE_SIGNING_SECRET`; the name is up to you.

The secret never goes into your pages, and never into a prompt for an AI coding agent. Set its value yourself.

## 2. Make a user token on your server

Where your server knows the signed-in person, add these lines. They make a short signed text, the user token. `user` stands for your app's signed-in person.

The token is a JWT signed with HS256, keyed on the text of your secret:

| Claim | What goes in it |
|-------|-----------------|
| `sub` | The same id your page passes to `identify()` as `userId`, as a string. |
| `tenant` | Optional: the same id your page passes as `tenantId`, as a string. Leave it out if your app has no companies or workspaces. |

Don't add an expiry (`exp`) or a key id (`kid`). A token that expires stops working in a tab left open, and rotating the secret (below) is how you cut old tokens off.

## 3. Pass the token to identify()

Get the token to the page for that person: print it into the page from your template, or add it to an endpoint your app already has for the current user. Send it with `Cache-Control: no-store`. Then pass it to `identify()`:

```javascript
// Lets the calls below run before our script has finished loading. Keep it first.
window.HelpAlive = window.HelpAlive || { q: [] };
["identify", "reset", "setConsent", "track"].forEach((m) => {
  if (!HelpAlive[m]) HelpAlive[m] = (...args) => HelpAlive.q.push([m, args]);
});

// In place of your identify() call from step 1.
// The token already says who the person is and which company they belong to.
HelpAlive.identify({
  userToken,                    // the token your server made for this person
  tenantName: company.name,     // optional: the company's name, shown in your dashboard
  displayName: user.name,       // optional
  email: user.email,            // optional
  role: user.role,              // optional: e.g. "admin", "editor", "viewer"
  plan: company.plan,           // optional: e.g. "free", "pro", "enterprise"
  createdAt: user.createdAt,    // optional: signup date, Unix time in seconds
})
```

The token says who the person is and which company they belong to, so you no longer pass `userId` or `tenantId`. If you pass a different one beside the token, the token wins and the browser console shows a warning.

## With an AI coding agent

Step 4 of the setup page has a prompt for Claude Code, Codex, Cursor or GitHub Copilot. It makes the token on your server, passes it to `identify()`, and adds `HELPALIVE_SIGNING_SECRET` to your list of environment variables with no value. You add the secret's value yourself, so it never goes into a prompt.

## 4. Check that it works

Sign in to your app and open the agent. Then press the refresh button on the setup page. The **Users are verified** line says what arrived:

| The line says | What it means |
|---------------|---------------|
| Verified people are arriving | Valid user tokens are reaching HelpAlive. |
| No token yet | Your pages don't send a token yet. |
| Tokens arrive but don't check out | Use the current signing secret, and make the token's `sub` the same id your page passes as `userId`. |
| Tokens arrive but have expired | Leave the expiry out of the token. |

HelpAlive records each kind of result at most every 15 minutes, so a fix you just made can take up to 15 minutes to show.

## 5. Only allow verified users

Once verified people are arriving, you can turn on **Only allow verified users**, below the check. Until you turn it on, nobody is turned away.

With it on, only people with a valid user token can use the agent and its guides. HelpAlive refuses every request without one, whether it names a user or not. Turn it on once every page that calls `identify()` sends a token.

## Rotating the secret

Click **Rotate** next to your secret and put the new one in `HELPALIVE_SIGNING_SECRET` on your server. Nothing in your code changes. The previous secret keeps working until you rotate again, so nobody is refused while you roll it out. If you are rotating because a secret leaked, rotate once more after your server uses the new one, and the leaked one stops working.

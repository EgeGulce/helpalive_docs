`identify()` is the one call you write yourself, besides the tag. It tells HelpAlive who is signed in, and the agent only appears once it has run.

## When to call it

Wherever your app already knows the signed-in person: right after login, and on every page load while they stay signed in. Calling it again with the same details is safe.

Keep these four lines above your first call. They let your code call HelpAlive before our script has finished loading, and our script replays the calls in order:

```javascript
// Lets the calls below run before our script has finished loading. Keep it first.
window.HelpAlive = window.HelpAlive || { q: [] };
["identify", "reset", "setConsent", "track"].forEach((m) => {
  if (!HelpAlive[m]) HelpAlive[m] = (...args) => HelpAlive.q.push([m, args]);
});
```

## The call

```javascript
// On every page while someone is logged in, starting right after login
HelpAlive.identify({
  userId: user.id,              // your own id for this person
  tenantId: company.id,         // optional: their company or workspace; leave out if your app has none
  tenantName: company.name,     // optional: the company's name, shown in your dashboard
  displayName: user.name,       // optional
  email: user.email,            // optional
  role: user.role,              // optional: e.g. "admin", "editor", "viewer"
  plan: company.plan,           // optional: e.g. "free", "pro", "enterprise"
  createdAt: user.createdAt,    // optional: signup date, Unix time in seconds
})
```

Only `userId` is required. Fill the optional fields your app has, and delete the others. In a TypeScript file, see [Installation](/installation#2-tell-helpalive-who-is-signed-in) for the one declaration it needs.

| Field | Required | What it is |
|-------|----------|------------|
| `userId` | Yes | Your own id for this person. It must not change, so don't use an email address if people can change theirs. |
| `tenantId` | No | Their company, workspace or account id, if your app has them. Leave it out if it doesn't: everyone then belongs to one group, `"default"`. |
| `tenantName` | No | The company's name, shown in your dashboard in place of the id. |
| `displayName` | No | The person's name, for example `"Priya Sharma"`. |
| `email` | No | Their email address, shown and searchable in your dashboard. |
| `role` | No | Their role in your app, for example `"admin"`, `"editor"` or `"viewer"`. |
| `plan` | No | Their plan, for example `"free"`, `"pro"` or `"enterprise"`. |
| `createdAt` | No | When they signed up, as Unix time in seconds (for example `1704067200` for 1 January 2024). Milliseconds and date strings are ignored; with `data-debug` on the tag, the console says why. |
| `userToken` | No | The user token your server makes, once you [verify your users](/sdk/verify-users). With a token, `userId` and `tenantId` come from the token, so you don't pass them. |

## Logging out

Call `reset()` in your logout code, apart from your `identify()` call, and wherever your app ends a session (for example where it notices a request came back signed out):

```javascript
// In your logout code, and wherever your app ends a session. Until this runs,
// the browser keeps the person, and the next visitor's events count as theirs.
HelpAlive.reset()
```

It also closes the agent, so the next person on the same browser never sees the last one's chat.

## Switching company without reloading

If people can switch company or workspace without a page reload, call `identify()` again with the new `tenantId` after the switch. HelpAlive counts what they do from then on under the new one.

Once you [verify your users](/sdk/verify-users), the company comes from the user token, and a `tenantId` passed beside it is ignored. Get a new token for the new company from your server and pass that to `identify()` instead.

## Before identify() runs

Nothing is sent for a visitor until `identify()` runs. Events wait in the page and are dropped if the visitor leaves without signing in, and the agent doesn't appear for them.

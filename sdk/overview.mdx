The HelpAlive SDK is the data foundation for everything else in the product. It's a small browser script that auto-captures user behavior, identifies users and tenants for analytics, and lets the AI chatbot read fresh page context at chat time.

## At a glance

| | |
|---|---|
| **Size** | ~11 KB gzipped |
| **Runtime dependencies** | None |
| **Distribution** | CDN script tag or `@helpalive/sdk` on npm |
| **Loading** | Async, non-blocking |
| **Browser support** | Evergreen browsers (Chrome, Edge, Firefox, Safari) |
| **Global** | `window.HelpAlive` |

## What the SDK does

## What's auto-captured

The SDK observes the DOM and emits events with redacted selector hashes. You don't write tracking code or maintain a tag plan.

| Event | Description |
|-------|-------------|
| `pageview` | Initial load and SPA navigations (history API + hash changes). |
| `click` | Click on any element. Selector hashed, text content redacted. |
| `form_start` | First interaction with a form input — used for abandonment analysis. |
| `form_submit` | Form submission. |
| `rage_click` | Repeated clicks in a small area (frustration signal). |
| `scroll_depth` | Per-page max scroll percentage. |
| `dom_error` | `console.error` and unhandled JavaScript exceptions. |
| `exposure` | Per-page summary of visible interactive elements. Used by the chatbot to know what's on screen. |

## What's not captured

- **Keystrokes.** The SDK never logs `keydown` or `input` content.
- **Form values.** Submit events fire, but field values are not transmitted.
- **Password fields.** Always excluded.
- **PII patterns** (emails, phone numbers, national IDs, etc.). Stripped client-side before any payload leaves the browser; stripped again server-side in a dedicated drainer.

See [Privacy & redaction](/privacy/redaction) for the complete data model.

## Public API

The SDK exposes these methods on `window.HelpAlive`. Full signatures live in the [API reference](/sdk/api-reference).

| Method | Purpose |
|--------|---------|
| `init(options)` | Manual init when loading via npm. Not needed when using the script tag. |
| `identify(payload)` | Identify the user and tenant. Required before events are accepted by the backend. |
| `track(name, props?)` | Emit a custom event. |
| `flush()` | Force-flush queued events to the server. |
| `reset()` | Clear identity (call this on logout). |
| `getContext()` | Read the current page, identity, and session state. Used by the chatbot widget. |
| `setRealTimeMode(enabled)` | Drain queued events immediately. The chatbot turns this on while a chat is active. |
| `setConsent(consent)` | Set or change the user's consent preferences at runtime. |
| `notify(payload)` | Push a proactive notification into the widget. |
| `onNotification(cb)` | Subscribe to notifications. |
| `startGuide(guide, opts?)` | Lazy-load the guide engine and start an in-app guide. |
| `getSuggestions()` | Fetch suggested questions for the current page. |
| `shutdown()` | Tear down the SDK. |

## Event buffering

Events are buffered in memory until `identify()` lands. The buffer holds up to 100 events; if `identify()` is never called, events are dropped on page unload (anonymous sessions are not stored in production).

Once identified, the SDK flushes on a rolling schedule and on `visibilitychange` so events don't get lost when users tab away or close the page.

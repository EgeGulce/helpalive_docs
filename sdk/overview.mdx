The HelpAlive SDK is a small browser script that does three things: auto-captures user behavior, ties activity to real users and workspaces, and feeds the AI chatbot fresh page context whenever a user opens it. One script tag, one `identify()` call, and you're done.

## At a glance

| | |
|---|---|
| **Size** | ~11 KB gzipped |
| **Runtime dependencies** | None |
| **Distribution** | CDN script tag or `@helpalive/sdk` on npm |
| **Loading** | Async, non-blocking |
| **Browser support** | Evergreen browsers (Chrome, Edge, Firefox, Safari) |
| **Global** | `window.HelpAlive` |

## What's auto-captured

The SDK observes user behavior automatically — you don't write tracking code or maintain a tag plan. Every captured event is anonymized before transmission.

| Event | What we capture |
|-------|-----------------|
| `pageview` | Page loads, including in-app navigations (single-page apps work out of the box). |
| `click` | Clicks on buttons, links, and other interactive elements. Element identifiers are anonymized; text content is redacted. |
| `form_start` | The user begins filling out a form. Useful for abandonment analysis. |
| `form_submit` | The user submits a form. (We never capture the field values.) |
| `rage_click` | Repeated clicks on the same element — a strong frustration signal. |
| `scroll_depth` | How far a user scrolled on each page. |
| `dom_error` | JavaScript errors and console errors that occurred while the user was interacting. |
| `exposure` | A summary of which interactive elements were visible on the page. Helps the chatbot know what's on screen when a user asks a question. |

## What's not captured

- **Keystrokes.** The SDK never logs `keydown` or `input` content.
- **Form values.** Submit events fire, but field values are not transmitted.
- **Password fields.** Always excluded.
- **PII patterns** (emails, phone numbers, national IDs, etc.). Stripped in the browser before any payload leaves the page; stripped again on our servers before storage.

See [Privacy & redaction](/privacy/redaction) for the complete data model.

## Public API

The SDK exposes these methods on `window.HelpAlive`. Full signatures live in the [API reference](/sdk/api-reference).

| Method | Purpose |
|--------|---------|
| `init(options)` | Manually initialize the SDK. Only needed when loading via npm; the script tag auto-initializes. |
| `identify(payload)` | Identify the user and workspace. Required for events to flow. |
| `track(name, props?)` | Send a custom event for things autocapture can't see. |
| `flush()` | Send any queued events right away. |
| `reset()` | Clear identity (call this on logout). |
| `getContext()` | Read the current page, identity, and session state — used by the chatbot widget. |
| `setRealTimeMode(enabled)` | Send events instantly instead of in batches. The chatbot turns this on while a chat is active. |
| `setConsent(consent)` | Set or change the user's consent preferences at runtime. |
| `notify(payload)` | Push a proactive notification into the chatbot. |
| `onNotification(cb)` | Subscribe to notifications from your own code. |
| `startGuide(guide, opts?)` | Start an in-app guide programmatically. |
| `getSuggestions()` | Fetch suggested questions for the current page. |
| `shutdown()` | Tear down the SDK. |

## Event buffering

Events are buffered in memory until `identify()` runs. If a user never authenticates, the buffered events are dropped when they leave the page — anonymous sessions are never stored.

Once a user is identified, events are sent on a rolling schedule and whenever the page goes into the background, so events don't get lost when users switch tabs or close the page.

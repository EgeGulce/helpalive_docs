This page shows developers how to make HelpAlive wait for your cookie banner before it records activity. Use it where your rules require consent before analytics.

## Prerequisites

- The HelpAlive tag is in your pages. See [Install the script](/installation).
- A cookie banner or consent tool that tells your code when a user accepts or declines.

## The two modes

| Mode | How to choose it | What happens |
|------|------------------|--------------|
| Default | Leave the tag as it is | HelpAlive records activity from the first page, once `identify()` has run. |
| Consent required | Add `data-consent="required"` to the tag | HelpAlive records no activity, and keeps its ids in memory only, until your page calls `setConsent({ analytics: true })`. |

`setConsent()` only has an effect in consent-required mode. Without `data-consent="required"`, HelpAlive records activity whatever `setConsent()` says.

<Note>
Consent mode covers activity recording only. The agent is not behind it. It still appears for signed-in users, and a chat or guide a user starts still sends what the agent needs. HelpAlive doesn't read Do Not Track or Global Privacy Control signals.
</Note>

## Set it up

<Steps>
  <Step title="Add data-consent to the tag">
    ```html
    <script src="https://cdn.helpalive.com/sdk/helpalive.js" data-api-key="YOUR_PROJECT_KEY" data-consent="required" async></script>
    ```
  </Step>
  <Step title="Pass the user's choice from your banner">
    Call `setConsent()` when the user accepts or declines, and on each page load once your banner knows the stored choice:

    ```javascript
    // When the user accepts analytics in your cookie banner
    HelpAlive.setConsent({ analytics: true })

    // When the user declines, or withdraws consent later
    HelpAlive.setConsent({ analytics: false })
    ```

    Keep the four queue lines from [Install the script](/installation) above these calls, so they work before our script has loaded.
  </Step>
  <Step title="Keep identify() and reset() as they are">
    Call `identify()` and `reset()` as the install shows. Consent doesn't change them.
  </Step>
</Steps>

## What happens before and after consent

- **Before consent:** HelpAlive records nothing. Activity that happens before consent is not kept for later. HelpAlive's ids live in memory only, so nothing of HelpAlive's is saved in the browser.
- **After `setConsent({ analytics: true })`:** HelpAlive saves its ids in the browser and records activity from then on.
- **After `setConsent({ analytics: false })`:** recording stops again, and new ids stay in memory only.

`analytics` is the only field. To keep the agent away from some users, leave them out of **Who gets it** on **Controls**. To stop recording one user for good, use **Settings → Privacy Management**.

## On a shared computer

To withdraw consent at logout as well, call both in your logout code:

```javascript
// In your logout code, and wherever your app ends a session
HelpAlive.reset()
HelpAlive.setConsent({ analytics: false })
```

## Check it works

1. Open your app in a private window with the browser's developer tools open on **Network**. Filter on `collect`.
2. Sign in and decline in your banner. Click around and load another page. No `collect` request appears.
3. Accept in your banner, click around and load another page. `collect` requests appear.

## Troubleshooting

<AccordionGroup>
  <Accordion title="HelpAlive records before the user accepts">
    The tag lacks `data-consent="required"`. Without it, `setConsent()` changes nothing.
  </Accordion>
  <Accordion title="Nothing is recorded after the user accepts">
    Your banner never calls `setConsent({ analytics: true })`, or calls it before the queue lines exist. Call it on every page load once the stored choice is known.
  </Accordion>
</AccordionGroup>

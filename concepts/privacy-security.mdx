HelpAlive is designed around a simple principle: the behavioral signals needed to guide users effectively are entirely separate from personal information. HelpAlive observes clicks, page paths, and interaction sequences — and nothing else. Sensitive data is identified and removed client-side before anything reaches HelpAlive's servers, so there is no risk of PII exposure through a data breach, a misconfiguration, or a vendor access incident.

## What HelpAlive collects

HelpAlive captures behavioral signals only:

- **Page paths** — which URLs or routes a user visits and in what order
- **Click interactions** — which elements a user clicks, and the sequence of those clicks
- **Interaction timing** — how long a user spends on a step relative to the behavioral map
- **Session flow metadata** — where in a defined flow the user currently is

None of this data is tied to what a user types. HelpAlive never reads form inputs, search queries, free-text fields, or any keyboard input of any kind.

<Warning>
  HelpAlive does **not** collect typed text, form field values, passwords, search terms, or any keystroke data. If a user types their email address into a login form, that value is never observed, never stored, and never transmitted. HelpAlive has no mechanism to capture it.
</Warning>

## Client-side PII scrubbing with Microsoft Presidio

Even within behavioral signals, metadata can sometimes carry PII — for example, a URL that contains a user's email address, or a query parameter that includes an account token. HelpAlive runs [Microsoft Presidio](https://microsoft.github.io/presidio/) directly in the browser to detect and redact these patterns before any data leaves the page.

Presidio scans for and removes:

- Email addresses
- Phone numbers
- Credit card numbers
- API tokens and secrets
- Other common PII patterns defined in the Presidio entity registry

Because scrubbing runs client-side, PII is removed before transmission — not after. There is no window during which raw data is held server-side pending processing.

<Info>
  Microsoft Presidio is an open-source PII detection and anonymization framework maintained by Microsoft. You can review its entity detection coverage and anonymization techniques at the [Presidio documentation site](https://microsoft.github.io/presidio/).
</Info>

## Consent mode for GDPR and CCPA

HelpAlive ships with consent-mode support for both GDPR and CCPA out of the box. Session observation does not begin until consent has been granted according to your configured consent framework. If a user declines or withdraws consent, HelpAlive stops collecting and discards any buffered session data for that user immediately.

No additional configuration is required to enable consent mode. HelpAlive reads from the standard consent signals your existing consent management platform (CMP) already emits.

## Data in transit

All session data transmitted from the browser to HelpAlive's servers is encrypted using TLS. HelpAlive does not use unencrypted transport for any data, including behavioral signals.

## Summary

| Category | HelpAlive behavior |
|---|---|
| Typed text and form values | Never collected |
| PII in URLs or metadata | Scrubbed client-side by Microsoft Presidio before transmission |
| Behavioral signals (clicks, paths) | Collected and used to build the behavioral map |
| GDPR / CCPA consent | Built-in consent-mode support; collection pauses until consent is granted |
| Data in transit | Encrypted via TLS |

The HelpAlive quickstart is the four steps from a new account to the agent answering inside your app. It is for whoever sets HelpAlive up: an admin, with a developer for step 1.

The steps are the same four as **Settings → Setup & API Key** in your dashboard. That page fills in your project key for you, and each step turns green by itself once HelpAlive sees it working.

## Quickstart at a glance

- Step 1, for your developer: add the HelpAlive tag to every page, and call `identify()` for the signed-in person.
- Step 2: on **Train**, add your help or docs site or upload a file, then press **Publish**.
- Step 3: try the agent in your own app with **Test it on your app**, then turn it on for your users on **Controls**.
- Step 4, optional and recommended: your server signs each user id, so that with **Only allow verified users** on, nobody can use the agent as someone else.
- The agent appears only for signed-in people your app identifies.

## Prerequisites

- A HelpAlive account. Sign up with your work email, enter the 6-digit code we email you, and fill in your profile and your organization. Then add a card to start your 7-day free trial; nothing is charged that day. See [Billing and usage](/dashboard/billing#free-trial).
- Access to your app's code, or to its Google Tag Manager container.
- Your help center, docs site or help files.

## How to set up HelpAlive

<Steps>
  <Step title="Add HelpAlive to your app">
    Your developer, about 10 minutes. Two pieces of code: a tag that loads HelpAlive on every page, and one call that tells it who is signed in. The agent only appears for signed-in people.

    Paste the tag into the `<head>` of every page. **Settings → Setup & API Key** shows it with your project key already in it.

    ```html
    <!-- Paste before </head> -->
    <script src="https://cdn.helpalive.com/sdk/helpalive.js" data-api-key="YOUR_PROJECT_KEY" async></script>
    ```

    Then, wherever your app knows the signed-in person, tell HelpAlive who they are. Do this right after login and on every page load while they stay signed in.

    ```javascript
    // Lets the calls below run before our script has finished loading. Keep it first.
    window.HelpAlive = window.HelpAlive || { q: [] };
    ["identify", "reset", "setConsent", "track"].forEach((m) => {
      if (!HelpAlive[m]) HelpAlive[m] = (...args) => HelpAlive.q.push([m, args]);
    });

    ```

    <Tabs>
      <Tab title="B2B: users belong to tenants">
        A tenant refers to a customer company or workspace, and its users sign in under it. `tenantId` and `tenantName` say which tenant each user belongs to. Some users have no tenant? Leave both out for them: your dashboard groups them as **B2C customers**.

        ```javascript
        // On every page while someone is logged in, starting right after login
        HelpAlive.identify({
          userId: String(user.id),      // required: your own id for this person
          tenantId: String(company.id), // required: their company or workspace
          tenantName: company.name,     // required: the company's name, shown in your dashboard
          displayName: user.name,       // required: the person's name (or their email), shown in your dashboard
          email: user.email,            // optional
          role: user.role,              // recommended, helps the agent
          plan: company.plan,           // recommended, helps the agent
          createdAt: user.createdAt,    // optional: signup date, Unix time in seconds
        })
        ```
      </Tab>
      <Tab title="B2C: users have no tenant">
        Each user signs up on their own, with no company or workspace around them, so leave out `tenantId` and `tenantName`. Your dashboard groups them as **B2C customers**.

        ```javascript
        // On every page while someone is logged in, starting right after login
        HelpAlive.identify({
          userId: String(user.id),      // required: your own id for this person
          displayName: user.name,       // required: the person's name (or their email), shown in your dashboard
          email: user.email,            // optional
          plan: user.plan,              // recommended, helps the agent
          createdAt: user.createdAt,    // optional: signup date, Unix time in seconds
        })
        ```
      </Tab>
    </Tabs>

    Put this in your logout code, apart from the code above:

    ```javascript
    // In your logout code, and wherever your app ends a session.
    HelpAlive.reset()
    ```

    `userId` and `displayName` are always required, and `tenantId` and `tenantName` too in a B2B app. [Install the script](/installation) covers where the tag goes in each framework, Google Tag Manager, TypeScript and the prompt for an AI coding agent. [Identify users](/sdk/identify) lists every `identify()` field.
  </Step>

  <Step title="Train the agent on your product">
    Anyone on your team. Open **Train** and choose **Add your help or docs site** or **Upload a file**. When the crawl finishes, press **Publish** in the bar at the top of the dashboard. The agent answers your users only from what is published. See [Train](/dashboard/train) and [Publishing](/dashboard/publishing).
  </Step>

  <Step title="Test it on your app">
    Anyone on your team, before your users see it. In step 3 of **Settings → Setup & API Key**, press **Test it on your app**. It opens the dashboard's **Test** page, which walks you through trying the agent in your own app, in your browser only. Nothing changes for your users. See [Test it on your app](/dashboard/test#test-it-on-your-app).

    When your test looks right, turn the agent on for your users on **Controls**. See [Controls](/dashboard/controls).
  </Step>

  <Step title="Verify your users (optional, recommended)">
    Your developer, about 15 minutes. HelpAlive works fully without this step. Without it, HelpAlive trusts the user id your page sends. With it, your server signs each id, and once you turn on **Only allow verified users**, nobody can use the agent as someone else. See [Setup & API Key](/dashboard/setup) and [Verify users](/sdk/verify-users).
  </Step>
</Steps>

<Note>
If someone already had your app open when you turned the agent on, their browser still remembers that it was off. They see the chat button within a minute or a few page loads. People who open your app later see it on their first page.
</Note>

## Check it works

At the top of **Settings → Setup & API Key**, the band says how many of the 4 steps are done and what to do next. Each step in the list under it gets a check once HelpAlive sees it working.

The checks need a real visit: once the tag is live, open your app, sign in, click around, and come back. You don't need to refresh, because the page checks again when you return. When the first three steps have a check, the band says your agent is ready for your users.

## Troubleshooting

- **The step 3 card is grayed out.** You can't test the agent before a source is published. Publish one on **Train** first.
- **The tag is on the page but nothing appears.** The agent only shows after `identify()` runs for a signed-in person. Check that your code calls it on every page load, and that `userId` is not empty.
- **Nothing shows after you switched it on.** Wait a minute and load a few pages, as in the note above. Check that **Who gets it** includes you.
- **Controls says "Your agent is off for your users until you subscribe."** Subscribe on **Settings → Billing and usage**. See [Billing and usage](/dashboard/billing).

## Still stuck?

Email [support@helpalive.com](mailto:support@helpalive.com). To help us answer quickly, include:

- the address of a page where the problem happens, and the browser you used;
- which checks on **Settings → Setup & API Key** are green;
- what the browser console shows with `data-debug` on the tag.

Your project key is public, which means that you can include it. Never send your signing secret.

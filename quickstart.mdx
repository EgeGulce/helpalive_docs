Getting HelpAlive running takes two steps: paste a script tag into your HTML, then call `identify()` when a user logs in. There are no backend changes, no event-tagging schemas, no framework lock-in.

<Steps>
  <Step title="Add the script tag">
    Paste the snippet into your HTML — inside `<head>` or just before `</body>`. It loads on every page of your app.

    ```html
    <script
      src="https://cdn.helpalive.com/sdk/helpalive.js"
      data-api-key="YOUR_API_KEY"
      async>
    </script>
    ```

    Replace `YOUR_API_KEY` with the key shown in your dashboard under **Settings → Integration**.

    <Note>
      The script is ~11 KB gzipped, has no runtime dependencies, and loads asynchronously. It exposes `window.HelpAlive` once ready and queues any calls made before it finishes loading.
    </Note>
  </Step>

  <Step title="Identify your user after login">
    Once the user authenticates, call `HelpAlive.identify()` with their stable user ID and a tenant ID. Both are required.

    ```javascript
    HelpAlive.identify({
      userId:     "user_8x92k",      // required: stable app user ID
      tenantId:   "acme-corp",       // required: workspace/org ID, or "default"
      tenantName: "Acme Corp",       // optional: workspace name
      displayName:"Priya Sharma",    // optional: full name
      email:      "priya@acme.com",  // optional: for search/display
      role:       "admin",           // optional: admin / editor / viewer
      plan:       "pro"              // optional: free / pro / enterprise
    });
    ```

    If your app doesn't have multi-tenancy, pass `tenantId: "default"`.

    <Tip>
      If `identify()` runs before the SDK finishes loading, the call is queued and flushed once the script is ready — no race-condition handling required on your side.
    </Tip>
  </Step>

  <Step title="Verify the connection">
    1. Log into your app and click around a few pages.
    2. Open the HelpAlive dashboard and go to **Settings → Integration**.
    3. The integration status should flip to **Active** within a few seconds.
    4. **Tenant Management** will list your workspace once identify data starts arriving.
  </Step>
</Steps>

## What you get with the two-step setup

Once the script and `identify()` call are in place, HelpAlive starts:

- **Auto-capturing** clicks, form submits, pageviews, rage clicks, and DOM errors — no event tagging required.
- **Building user and tenant profiles** so adoption metrics are tied to real accounts.
- **Powering the AI chatbot** if you've enabled it (the widget loads automatically).

## Common stumbles

<AccordionGroup>
  <Accordion title="Content Security Policy blocks the script">
    Add the HelpAlive origin to your CSP header:

    ```
    script-src  https://cdn.helpalive.com;
    connect-src https://api.helpalive.com;
    ```
  </Accordion>
  <Accordion title="Single-page apps and route changes">
    The SDK detects history-API navigations automatically — no `pageview` call needed when your router changes the URL.
  </Accordion>
  <Accordion title="Calling identify() before the script is ready">
    Safe. The SDK queues calls made before it finishes loading and replays them once `window.HelpAlive` is available. You don't need a `window.HelpAlive?.` guard.
  </Accordion>
  <Accordion title="No tenant ID in your app">
    Pass `tenantId: "default"`. You can switch to real tenant IDs later without re-identifying users.
  </Accordion>
</AccordionGroup>

This page shows your developer how to add HelpAlive to a web app by hand: one tag, one `identify()` call and one `reset()` call. It is complete on its own, so an AI coding agent can follow it without reading any other page.

**Settings → Setup & API Key** shows the same code with your project key already filled in. It also offers two other ways in: [a prompt for an AI coding agent](/sdk/ai-coding-agents) and [Google Tag Manager](/sdk/google-tag-manager).

## Prerequisites

- Your project key, from **Settings → Setup & API Key**. It is public: it goes in your pages and is safe to show.
- Access to the layout or template that every page of your app shares.
- Your developer, about 10 minutes.

## The rules

Follow all of these. A missed rule usually fails without any error on screen.

1. Put the tag in the `<head>` of every page, with `data-api-key` set to your project key.
2. Keep the four queue lines above your first `HelpAlive` call.
3. Call `identify()` for the signed-in user right after login, and on every page load while they stay signed in.
4. Pass `userId` and `tenantId` as text or a number. `42` and `"42"` are the same person.
5. Use a `userId` that never changes. Don't use an email address if users can change theirs.
6. Pass `tenantId` only if your app has companies, workspaces or accounts. Leave it out otherwise.
7. Pass `role`, `plan`, `displayName`, `email` and `tenantName` as text. A field of the wrong type is left out. Pass `createdAt` as Unix time in seconds.
8. Call `reset()` in your logout code, and keep it apart from `identify()`. Never put it straight after `identify()`.
9. If your app sends a Content Security Policy, add our sources, and put your nonce on our tag if your policy uses one.

## Install it

<Steps>
  <Step title="Paste the tag into the head of every page">
    ```html
    <!-- Paste before </head> -->
    <script src="https://cdn.helpalive.com/sdk/helpalive.js" data-api-key="YOUR_PROJECT_KEY" async></script>
    ```

    Replace `YOUR_PROJECT_KEY` with your key, or copy the tag from the setup page, where the key is already in it. Put it in the one file every page shares:

    | Your app | Where the tag goes |
    |----------|--------------------|
    | Rails, Django, Laravel, ASP.NET or any server-rendered app | The layout template every page uses |
    | React, Vue, Angular or Svelte (Vite and similar) | `index.html` |
    | Next.js | `app/layout.tsx`, or `pages/_document.tsx` |
    | Nuxt | `app.head` in `nuxt.config` |
    | Webflow, WordPress, Bubble and other builders | The site's custom code setting for the head |

    The tag loads in the background (`async`), so it doesn't hold up your page. [The JavaScript reference](/sdk/reference#script-tag-attributes) lists the other attributes the tag accepts.
  </Step>

  <Step title="Tell HelpAlive who is signed in">
    Put this wherever your app already knows the signed-in user: right after login, and on every page load while they stay signed in. Fill it in from your app's own user and company objects.

    ```javascript
    // Lets the calls below run before our script has finished loading. Keep it first.
    window.HelpAlive = window.HelpAlive || { q: [] };
    ["identify", "reset", "setConsent", "track"].forEach((m) => {
      if (!HelpAlive[m]) HelpAlive[m] = (...args) => HelpAlive.q.push([m, args]);
    });

    ```

    Then the call itself. Pick the tab that matches your app:

    <Tabs>
      <Tab title="B2B: users belong to tenants">
        Each customer company or workspace is a tenant, and its users sign in under it. `tenantId` and `tenantName` say which tenant each user belongs to. Some users have no tenant? Leave both out for them: your dashboard groups them as **B2C customers**.

        ```javascript
        // On every page while someone is logged in, starting right after login
        HelpAlive.identify({
          userId: String(user.id),      // required: your own id for this person
          tenantId: String(company.id), // required: their company or workspace
          tenantName: company.name,     // required: the company's name, shown in your dashboard
          displayName: user.name,       // required: the person's name (or their email), shown in your dashboard
          email: user.email,            // optional
          role: user.role,              // recommended, helps the agent
          plan: company.plan,           // recommended, helps the agent
          createdAt: user.createdAt,    // optional: signup date, Unix time in seconds
        })
        ```
      </Tab>
      <Tab title="B2C: users have no tenant">
        Each user signs up on their own, with no company or workspace around them, so leave out `tenantId` and `tenantName`. Your dashboard groups them as **B2C customers**.

        ```javascript
        // On every page while someone is logged in, starting right after login
        HelpAlive.identify({
          userId: String(user.id),      // required: your own id for this person
          displayName: user.name,       // required: the person's name (or their email), shown in your dashboard
          email: user.email,            // optional
          plan: user.plan,              // recommended, helps the agent
          createdAt: user.createdAt,    // optional: signup date, Unix time in seconds
        })
        ```
      </Tab>
    </Tabs>

    `userId` and `displayName` are always required. In a B2B app, `tenantId` and `tenantName` are required too; in a B2C app, leave them out. `role` and `plan` are recommended: the agent reads both, and without them it sees "unknown". The rest are optional: fill what your app has, and delete the others. `String()` keeps ids as text; numbers work too.

    The first four lines let your code call HelpAlive before our script has loaded. Our script replays the calls in order when it arrives. [Identify users](/sdk/identify) describes each field.
  </Step>

  <Step title="Forget them when they log out">
    Put this in your logout code, apart from the code above. Also put it wherever your app ends a session, for example where a request comes back signed out:

    ```javascript
    // In your logout code, and wherever your app ends a session. Until this runs,
    // the browser keeps the person, and the next visitor's events count as theirs.
    HelpAlive.reset()
    ```

    Pasted straight after `identify()`, it would forget the user at once and the agent would never appear. `reset()` also closes the agent and clears its conversation from the browser.
  </Step>

  <Step title="Allow our hosts in your Content Security Policy, if you have one">
    Most apps don't send a `Content-Security-Policy` header and can skip this step. If yours does, add these sources to it without removing anything:

    ```text
    script-src https://cdn.helpalive.com;
    connect-src https://api.helpalive.com https://chat.helpalive.com;
    ```

    If your `script-src` uses a nonce, put the page's nonce on the HelpAlive tag, the same way your other scripts get theirs:

    ```html
    <script src="https://cdn.helpalive.com/sdk/helpalive.js" data-api-key="YOUR_PROJECT_KEY" nonce="YOUR_PAGE_NONCE" async></script>
    ```

    No `style-src` change and no `'unsafe-inline'` are needed. [Content Security Policy](/sdk/csp) explains each source.
  </Step>
</Steps>

## TypeScript

If the code from step 2 is in a TypeScript file, tell TypeScript about HelpAlive once, in a `.d.ts` file your project includes:

```typescript
// In a .d.ts file your project includes, for example helpalive.d.ts
declare var HelpAlive: any
```

Then give the queue line's rest argument a type:

```typescript
if (!HelpAlive[m]) HelpAlive[m] = (...args: unknown[]) => HelpAlive.q.push([m, args]);
```

## Single-page apps

- HelpAlive records page views by itself when your router changes the address. You don't call anything on route changes.
- One `identify()` per page load is enough. Calling it again with the same details is safe.
- React StrictMode runs effects twice in development. Two `identify()` calls for the same user are harmless.
- If a different user signs in without a page reload, call `identify()` with the new user. HelpAlive closes the previous user's agent first.

## Check it works

<Steps>
  <Step title="Sign in to your app">
    Use a test account and open a page. Wait a few seconds.
  </Step>
  <Step title="Look for the agent">
    The round chat button appears in a corner once the agent is switched on on **Controls** and has published docs from **Train**. Until then, the steps below still tell you the install works.
  </Step>
  <Step title="Open the setup checks">
    The checks need a real visit: once the tag is live, open your app, sign in, click around, and come back. The page checks again when you return. Then **Settings → Setup & API Key** shows the **Is it working?** checks turning green one by one:

    | Check | It turns green when |
    |-------|---------------------|
    | **HelpAlive is on your pages** | Our script started on one of your pages, or sent an event, in the last week. |
    | **It knows who is signed in** | A page called `identify()` for a signed-in user. |
    | **The agent has your docs** | At least one source on **Train** is published. |
    | **A test has run in your app** | An assist or chat ran from a test link made by **Test it on your app**. |
    | **Users are verified** (optional) | Valid user tokens are arriving. See [Verify users](/sdk/verify-users). |

    When the four required checks are green, the panel says **Everything is working.**
  </Step>
</Steps>

To see what HelpAlive does on a page, add `data-debug` to the tag while you test. It logs to the browser console. Remove it before you ship.

## Troubleshooting

<AccordionGroup>
  <Accordion title="HelpAlive is on your pages stays grey">
    - The build with the tag isn't live where you're testing yet.
    - The tag has no `data-api-key`. Without it, nothing starts and nothing is logged.
    - Your Content Security Policy blocks the script. Open the browser console and look for an error that names `helpalive.js` or `Content Security Policy`.
    - An ad blocker or privacy extension blocks it. Try a private window with extensions off.
  </Accordion>
  <Accordion title="The script is seen, but nobody is recognized">
    `identify()` isn't running, or it was refused. Check that it runs after login and on every page load, and that the four queue lines come before it. Check that `userId` is not empty. Add `data-debug` to the tag to see the reason in the console.
  </Accordion>
  <Accordion title="Everything is green, but the agent doesn't appear">
    The agent appears only for signed-in users it is switched on for, on **Controls**. A page that was already open picks up a change within a minute or a few page loads. [Troubleshooting](/sdk/troubleshooting) covers the other causes.
  </Accordion>
</AccordionGroup>

Email [support@helpalive.com](mailto:support@helpalive.com). To help us answer quickly, include:

- the address of a page where the problem happens, and the browser you used;
- which checks on **Settings → Setup & API Key** are green;
- what the browser console shows with `data-debug` on the tag.

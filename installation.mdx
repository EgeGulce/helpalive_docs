HelpAlive installs entirely in the browser. There's no server SDK, no schema migration, no pipeline to deploy. You add one script tag and one `identify()` call, and the SDK handles the rest.

This page covers:

- The script tag and CSP requirements
- Loading via npm
- Framework-specific examples (React, Vue, Angular, HTML)
- Identifying users and tenants
- What the SDK captures automatically

## Script tag (recommended)

Paste this into your HTML, inside `<head>` or immediately before `</body>`. It loads on every page of your app.

```html
<script
  src="https://cdn.helpalive.com/sdk/helpalive.js"
  data-api-key="YOUR_API_KEY"
  async>
</script>
```

The loader auto-initializes from `data-*` attributes, so no extra `init()` call is needed.

| Attribute | Required | Description |
|-----------|----------|-------------|
| `data-api-key` | Yes | Your project API key from **Settings → Integration**. |
| `data-endpoint` | No | Override the events endpoint. Defaults to `https://api.helpalive.com`. |
| `data-chat-endpoint` | No | Override the chatbot endpoint. Defaults to the chat backend wired to your project. |
| `data-debug` | No | Set to `"true"` to log SDK activity to the console. |

### Content Security Policy

If you ship a CSP header, allow the HelpAlive origins:

```
script-src  https://cdn.helpalive.com;
connect-src https://api.helpalive.com;
```

## npm package

For bundlers and frameworks that prefer ES modules:

```bash
npm install @helpalive/sdk
```

```javascript
import HelpAlive from "@helpalive/sdk";

HelpAlive.init({
  apiKey: "YOUR_API_KEY"
});
```

When you load via npm, you must call `init()` yourself — the auto-init only fires for the script-tag form.

<Note>
  The script tag loads from a CDN with edge caching and is the fastest path for most apps. Use the npm package only if you need the SDK to be part of your bundle (offline-first apps, strict CSP environments).
</Note>

## Framework examples

The pattern is the same everywhere: load once on app start, call `identify()` after the user authenticates.

  <Tab title="React">
    ```jsx
    // src/App.jsx
    import { useEffect } from "react";

    export default function App({ user }) {
      // Inject the script once on mount
      useEffect(() => {
        const s = document.createElement("script");
        s.src = "https://cdn.helpalive.com/sdk/helpalive.js";
        s.dataset.apiKey = "YOUR_API_KEY";
        s.async = true;
        document.head.appendChild(s);
      }, []);

      // Identify the user once they're available
      useEffect(() => {
        if (!user) return;
        window.HelpAlive?.identify({
          userId:      user.id,
          tenantId:    user.tenantId ?? "default",
          tenantName:  user.tenantName,
          displayName: user.name,
          email:       user.email,
          role:        user.role,
          plan:        user.plan
        });
      }, [user]);

      return <>{/* your app */}</>;
    }
    ```

    For Next.js, drop the `<script>` tag straight into `app/layout.tsx` (or `_document.tsx` on the pages router) instead of injecting it from `useEffect`.

## Identify your users and tenants

Call `HelpAlive.identify()` once per session, immediately after authentication. `userId` and `tenantId` are required; everything else is optional but improves analytics and chatbot personalization.

```javascript
HelpAlive.identify({
  userId:      "user_8x92k",   // required
  tenantId:    "acme-corp",    // required (use "default" if no multi-tenancy)
  tenantName:  "Acme Corp",
  displayName: "Priya Sharma",
  email:       "priya@acme.com",
  role:        "admin",
  plan:        "pro",
  createdAt:   "2024-11-03T09:00:00Z"
});
```

See the [identify guide](/sdk/identify) for the full field reference and behavior around tenant switching, anonymous sessions, and event buffering.

## What gets captured automatically

Once the script and `identify()` call are in place, the SDK auto-captures:

- **Pageviews** — including SPA navigations (history API, hash changes).
- **Clicks** — with redacted selector hashes for grouping.
- **Form submits and form-start events** — for funnel and abandonment analysis.
- **Rage clicks** — repeated clicks in a small area.
- **Scroll depth** — per-page max-scroll telemetry.
- **DOM errors** — `console.error` and unhandled exceptions.
- **Per-page exposure** — a summary of visible interactive elements, used by the chatbot for context.

You don't tag events, define funnels, or write per-feature instrumentation. The model is autocapture — the only manual call you ever need is `identify()`.

## Privacy by default

PII is redacted in the browser before any payload is sent, then again on the server in a dedicated drainer. The SDK never captures keystrokes, form input values, or password fields. See the [privacy overview](/privacy/overview) for the full data model.

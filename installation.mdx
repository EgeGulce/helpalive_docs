HelpAlive installs in the browser. Two pieces of code: a tag that loads HelpAlive on every page, and one call that tells it who is signed in. The agent only appears for signed-in people.

Your setup page, **Settings → Setup & API Key**, shows all of this with your project key already filled in. It offers three ways to do it:

- [With an AI coding agent](#with-an-ai-coding-agent): paste one prompt into the tool your developer already uses.
- [Add it yourself](#add-it-yourself): copy the tag and the identify() call.
- [Google Tag Manager](#google-tag-manager): two Custom HTML tags and a data layer push.

## With an AI coding agent

Open your app's code in Claude Code, Codex, Cursor or GitHub Copilot and paste the prompt from the setup page. It adds the tag and the identify() call, adds our hosts to your Content Security Policy if your app has one, and lists the files it touched.

The prompt carries every instruction itself, including your project key, so the agent doesn't need to read this page.

## Add it yourself

### 1. Paste the tag into the head of every page

```html
<!-- Paste before </head> -->
<script src="https://cdn.helpalive.com/sdk/helpalive.js" data-api-key="YOUR_PROJECT_KEY" async></script>
```

Copy it from the setup page, where `YOUR_PROJECT_KEY` is already your key. Put it in the one file every page shares:

| Your app | Where the tag goes |
|----------|--------------------|
| Rails, Django, Laravel, ASP.NET or any server-rendered app | The layout template every page uses |
| React, Vue, Angular or Svelte (Vite and similar) | `index.html` |
| Next.js | `app/layout.tsx`, or `pages/_document.tsx` |
| Nuxt | `app.head` in `nuxt.config` |
| Webflow, WordPress, Bubble and other builders | The site's custom code setting for the head |

The tag loads in the background (`async`), so it never slows your page down.

| Attribute | Required | What it does |
|-----------|----------|--------------|
| `data-api-key` | Yes | Your project key, from **Settings → Setup & API Key**. |
| `async` | Recommended | Loads the script without holding up your page. |
| `data-debug` | No | Logs what HelpAlive does to the browser console. For development only. |
| `data-consent="required"` | No | Records nothing until your page calls `HelpAlive.setConsent({ analytics: true })`. See [Consent](/sdk/consent). |

### 2. Tell HelpAlive who is signed in

Put this wherever your app already knows the signed-in person: right after login, and on every page load while they stay signed in.

```javascript
// Lets the calls below run before our script has finished loading. Keep it first.
window.HelpAlive = window.HelpAlive || { q: [] };
["identify", "reset", "setConsent", "track"].forEach((m) => {
  if (!HelpAlive[m]) HelpAlive[m] = (...args) => HelpAlive.q.push([m, args]);
});

// On every page while someone is logged in, starting right after login
HelpAlive.identify({
  userId: user.id,              // your own id for this person
  tenantId: company.id,         // optional: their company or workspace; leave out if your app has none
  tenantName: company.name,     // optional: the company's name, shown in your dashboard
  displayName: user.name,       // optional
  email: user.email,            // optional
  role: user.role,              // optional: e.g. "admin", "editor", "viewer"
  plan: company.plan,           // optional: e.g. "free", "pro", "enterprise"
  createdAt: user.createdAt,    // optional: signup date, Unix time in seconds
})
```

Only `userId` is required. Use `tenantId` if your app has companies or workspaces. The rest are optional: fill what your app has, and delete the others. [Identify](/sdk/identify) describes each field.

The first four lines let your code call HelpAlive before our script has finished loading. Keep them above your first call.

<Accordion title="Is this file TypeScript?">
  Tell TypeScript about HelpAlive once, in a `.d.ts` file your project includes:

  ```typescript
  // In a .d.ts file your project includes, for example helpalive.d.ts
  declare var HelpAlive: any
  ```

  and give the queue line a type:

  ```typescript
  if (!HelpAlive[m]) HelpAlive[m] = (...args: unknown[]) => HelpAlive.q.push([m, args]);
  ```
</Accordion>

### 3. Forget them when they log out

Put this in your logout code, apart from the code above, and wherever your app ends a session (for example where it notices a request came back signed out):

```javascript
// In your logout code, and wherever your app ends a session. Until this runs,
// the browser keeps the person, and the next visitor's events count as theirs.
HelpAlive.reset()
```

Pasted straight after `identify()`, it would forget the person at once.

## Google Tag Manager

### 1. Add the HelpAlive tag

In Tag Manager: **Tags → New → Custom HTML**. Paste this and set the trigger to **All Pages**.

```html
<script>
(function(){
  var s=document.createElement("script");
  s.src="https://cdn.helpalive.com/sdk/helpalive.js";
  s.setAttribute("data-api-key","YOUR_PROJECT_KEY");
  s.async=true;
  document.head.appendChild(s);
})();
</script>
```

### 2. Push the signed-in person to the data layer, from your app

Right after login, and on every page load while they stay signed in. Leave out the lines you don't have.

```javascript
// On every page while someone is logged in, starting right after login
dataLayer.push({
  event: "helpalive_identify",
  helpalive_user_id: user.id,                    // IMPORTANT: Replace with your user's stable ID
  helpalive_tenant_id: company.id,               // optional; their company or workspace, if your app has them
  helpalive_tenant_name: company.name,           // optional; workspace display name
  helpalive_display_name: user.name,             // optional; user's full name
  helpalive_email: user.email,                   // optional; user email
  helpalive_role: user.role,                     // optional; e.g. "admin", "editor"
  helpalive_plan: user.plan,                     // optional; e.g. "free", "pro"
  helpalive_created_at: user.createdAt,          // optional; signup date (Unix seconds)
});
```

### 3. Add a second tag that passes it on

Custom HTML again, triggered by the custom event `helpalive_identify`. Create a **Data Layer Variable** for each `helpalive_` name in it (Variables → New → Data Layer Variable, version 2), and delete the lines for fields you don't push. Tag Manager won't publish a tag that names a variable you haven't created.

```html
<script>window.HelpAlive=window.HelpAlive||{q:[]};["identify","reset","setConsent","track"].forEach(function(m){HelpAlive[m]=HelpAlive[m]||function(){HelpAlive.q.push([m,[].slice.call(arguments)])}})</script>
<script>
  window.HelpAlive.identify({
    userId: {{helpalive_user_id}},
    tenantId: {{helpalive_tenant_id}},
    tenantName: {{helpalive_tenant_name}},
    displayName: {{helpalive_display_name}},
    email: {{helpalive_email}},
    role: {{helpalive_role}},
    plan: {{helpalive_plan}},
    createdAt: {{helpalive_created_at}}
  });
</script>
```

### 4. Forget them when they log out

In your logout code, and wherever your app ends a session, push this:

```javascript
// In your logout code, and wherever your app ends a session
dataLayer.push({ event: "helpalive_reset" });
```

Then add a third Custom HTML tag, triggered by the custom event `helpalive_reset`:

```html
<script>window.HelpAlive=window.HelpAlive||{q:[]};["identify","reset","setConsent","track"].forEach(function(m){HelpAlive[m]=HelpAlive[m]||function(){HelpAlive.q.push([m,[].slice.call(arguments)])}})</script>
<script>
  window.HelpAlive.reset();
</script>
```

Then **Submit** the container in Tag Manager. To verify your users through Tag Manager, see [Verify your users](/sdk/verify-users#with-google-tag-manager).

## Content Security Policy

Most apps don't need this. If your app sends a `Content-Security-Policy` header, add these sources to what you already have:

```
script-src https://cdn.helpalive.com;
connect-src https://api.helpalive.com https://chat.helpalive.com;
style-src 'unsafe-inline';
```

The `chat.helpalive.com` source is the agent's. Without it, the tag loads and events arrive, but the agent can't answer. The `style-src` line lets the agent draw its own styles. Without it, the agent's button shows unstyled at the top of your page.

## Check that it works

Sign in to your app and open a page. Then open **Settings → Setup & API Key**. The **Is it working?** panel has one line per step; press the refresh button to check again after trying your app.

| Line | It turns green when |
|------|---------------------|
| **HelpAlive is on your pages** | Our script started on one of your pages, or sent us an event, in the last week. If it reaches your pages but can't start, the line says to check the project key in the tag. |
| **It knows who is signed in** | A page called `identify()` for a signed-in person. |
| **The agent has your docs** | At least one source on **Agent → Train** is published and ready. A published source that is being re-crawled still counts, since the agent keeps answering from it. |
| **The agent answers in your app** | The agent is switched on and has answered at least one message in your app this month. |
| **Users are verified** (optional) | Valid user tokens are arriving. See [Verify your users](/sdk/verify-users). |

When every needed line is green, the panel says **Everything is working.**

<AccordionGroup>
  <Accordion title="The first line stays grey">
    1. The build with the tag isn't live yet in the place you're testing.
    2. Your Content Security Policy blocks the script: see [above](#content-security-policy). Press F12, open **Console**, and look for a red error that mentions `helpalive.js` or `Content Security Policy`.
    3. An ad blocker or privacy extension blocks it. Try a private window with extensions off.
  </Accordion>
  <Accordion title="The script is seen, but nobody is recognized">
    `identify()` isn't running. Check that it runs after login and on every page load while the person stays signed in, and that the four queue lines come before it.
  </Accordion>
  <Accordion title="The agent doesn't appear">
    The agent only appears for signed-in people, once it is set up and switched on in the rollout settings on **Agent → Configuration** and you pressed **Save changes**, and only for the people you chose there. A page that was already open picks up the change on the next page load, so load one more page.
  </Accordion>
</AccordionGroup>

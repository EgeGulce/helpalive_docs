Every user identified through the SDK gets a profile in the dashboard. It's the surface your support and success teams use to answer "what's this user doing in our product?" without leaving HelpAlive.

## Where to find them

**Dashboard → Analyze → User profiles → [tenant] → [user]**

You can also reach a profile by:

- Clicking a user from a tenant detail page.
- Clicking the user reference in any chatbot conversation.
- Searching by email or display name from the global dashboard search.

## What's on the profile

<CardGroup cols={2}>
  <Card title="Identity" icon="user">
    `userId`, `tenantId`, display name, email, role, plan, account age. Sourced from the most recent `identify()` call.
  </Card>
  <Card title="Activity timeline" icon="clock">
    A reverse-chronological log of pageviews, clicks, errors, and chatbot conversations.
  </Card>
  <Card title="Platforms" icon="monitor">
    Browsers, operating systems, mobile vs desktop, time zones.
  </Card>
  <Card title="Privacy status" icon="shield-check">
    Consent state, suppression flags, DSAR jobs in flight.
  </Card>
</CardGroup>

## Activity timeline

The timeline aggregates the most recent events for the user. Common event types you'll see:

| Event | Shown as |
|-------|----------|
| `pageview` | A row with the page title and URL. |
| `click` | A row with the redacted selector hash and surrounding page context. |
| `form_submit` | A row with the form's surrounding selector. |
| `rage_click` | Highlighted as a friction signal. |
| `dom_error` | Highlighted as a quality signal, with the error message. |
| `chatbot_conversation` | Expandable; shows messages and rating. |

Events are clipped to the most recent few hundred for performance. For deeper history, use the per-tenant export (when available on your plan).

## Sessions

Activity is grouped into sessions — contiguous bursts of activity separated by an idle gap. The default idle threshold is 30 minutes; this is configurable per customer in **Settings → Session policy**.

Each session shows:

- Start and end time.
- Page count.
- Event count.
- Whether the user opened the chatbot.

## Recent chatbot conversations

Conversations are linked from the activity timeline so support staff can see what the user asked the assistant and what answer they got. Each conversation shows:

- Page where the chat started.
- Full message thread (questions and answers).
- Rating, if the user gave one.
- Coverage classification (`covered`, `weak_retrieval`, etc.) — useful for spotting where the assistant let this user down.

## Privacy state

The profile surfaces the user's privacy state at a glance:

- **Consent** — `analytics: on/off`, `chat: on/off` from the most recent `setConsent()` call.
- **Tenant suppression** — if the user's tenant has been suppressed (no ingestion).
- **User suppression** — if this specific user has been suppressed.
- **DSAR** — any in-flight or completed deletion jobs, with status.

If a user has been DSAR-deleted, the profile shows a placeholder with the deletion timestamp instead of activity.

## Searching

The user search supports:

- **Display name** (case-insensitive substring).
- **Email** (case-insensitive substring).
- **userId** (exact match — useful for engineers debugging from logs).

Search is scoped to your customer; you only see your own users.

## Common workflows

<AccordionGroup>
  <Accordion title="Support looking up a customer who reports a bug">
    1. Search by email.
    2. Open the profile → scroll the activity timeline to the time the user reported the issue.
    3. Look for `dom_error`, `rage_click`, or repeated form submits near that time.
    4. If they used the chatbot, expand the conversation to see what they asked.
  </Accordion>
  <Accordion title="Success reviewing an at-risk account">
    1. Open the tenant from the audience list.
    2. Sort users by activity (most active first) → spot which seats are quiet.
    3. Click a quiet user → confirm they really aren't using the product.
    4. Cross-reference with their plan + role to spot an upsell or churn risk.
  </Accordion>
  <Accordion title="Honoring a delete request">
    See [DSAR deletion](/privacy/dsar) for the full flow — initiated from the user profile.
  </Accordion>
</AccordionGroup>

## Privacy guarantees on the profile

- Display name and email are visible to dashboard admins by design — you need them to do support and success work.
- Raw event content (clicked text, form values) is **never** shown — only redacted selectors and page metadata.
- Chatbot question text is shown because it's the only way to do support; question text is itself PII-redacted on storage.
- Profile data is scoped to your customer. Cross-customer access is impossible by construction.

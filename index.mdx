HelpAlive is an AI agent that lives inside your web app. It answers your users' questions from your own docs, and it does tasks for them or shows them how, one step at a time. You add one script and one `identify()` call, it works on any web app, and it reads the page's structure instead of taking screenshots.

This site is for the people who set HelpAlive up: the admin who configures it in the dashboard and the developer who installs it.

## HelpAlive at a glance

- **What it is:** an in-app AI agent. It runs in your user's browser, inside your app, and sees the page the user is on.
- **What it does:** it answers questions from the docs you publish, offers to do a task when the user wants it done, and hands back the steps only the user can take.
- **How you add it:** one script tag and one `identify()` call. You don't tag elements, describe your screens or build an API for it.
- **Who sees it:** only the signed-in people your app identifies, and only those you choose on **Controls**.
- **How it sees your app:** as structured text, with headings, visible text, and each button, link and field with its label. It never takes screenshots or records the screen.

## What your users get

- **Answers from your docs.** Users ask in their own words and get a short answer that fits the page they're on. Suggested questions under **"Ask about this page"** are made from the page, what the user has been doing, and your docs. See [Chat](/product/chat).
- **Tasks done for them, or shown to them.** When a user wants something done, the agent offers an assist. It does the steps itself, or highlights each control so the user clicks. See [Assists](/product/assists).
- **Help when they get stuck.** A nudge is a small message that offers help when a user runs into an error, a button that doesn't respond, or a save that fails. See [Nudges](/product/nudges).
- **A clear hand-back.** Steps only the user can do, such as uploading a file, go back to them.

You decide which of these each tenant or person gets, on **Controls**.

## How HelpAlive works

HelpAlive works in five stages, each one in your user's own signed-in session:

1. **It reads the page** as structured text, again at every step, so it works from what is on screen now.
2. **It answers from your published docs.** Drafts are never used for your users' answers, and your docs win when general knowledge disagrees.
3. **It offers a task only when it can be done in your app**, as a card under the answer. The card starts nothing by itself.
4. **It does the steps, or shows how**, one step at a time, and checks after each step that it landed.
5. **It hands back what only the user can do**, such as a password, a code from their phone, or a file upload.

Because it works through your app's own interface, it can do only what that user could do themselves. See [How HelpAlive works](/product/how-it-works) for the guarantees at each stage, and [How HelpAlive compares](/product/compare) for how it differs from help chatbots, product tours and MCP-based agents.

## Start here

<Steps>
  <Step title="Create your account">
    Sign up at [app.helpalive.com/signup](https://app.helpalive.com/signup). The [Quickstart](/quickstart) follows the same steps as **Settings → Setup & API Key**.
  </Step>
  <Step title="Add the script and identify()">
    Your developer adds one tag to your pages and one `identify()` call for the signed-in person. See [Install the script](/installation).
  </Step>
  <Step title="Teach it your product">
    On **Train**, add your help site or upload files, then publish them. See [Train](/dashboard/train).
  </Step>
  <Step title="Turn it on">
    On **Controls**, turn the agent on and choose who gets it. See [Controls](/dashboard/controls).
  </Step>
</Steps>

## Check it works

Sign in to your own app as a user who should get the agent. A round button appears in the corner of the page. Open it and ask a question your docs answer.

If the button doesn't appear, see [Troubleshooting](/sdk/troubleshooting).

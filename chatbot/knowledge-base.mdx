The HelpAlive chatbot grounds every answer in your knowledge base. You point us at your existing content — a docs site, files, or pasted text — and we handle the rest.

## What you can add

| Source | How to add | Best for |
|--------|------------|----------|
| **Docs site** | Crawl from a URL | Existing public help center or product docs |
| **PDF** | Upload a file | Onboarding guides, internal manuals, contracts |
| **Word documents (DOCX)** | Upload a file | Knowledge articles your team writes in Word |
| **Markdown** | Upload or paste | Technical docs you keep alongside your code |
| **Plain text** | Paste in the dashboard | Short FAQs, custom answers, special-case responses |

## Adding a knowledge source

Open the dashboard and go to **AI → Knowledge base → Add source**.

### Crawling a URL

Use this when you already have a docs site or help center. Configure:

- **Start URL** — the page to begin from.
- **Crawl depth** — how many link-hops deep to follow.
- **Stay on domain** — when on, the crawler ignores cross-domain links.
- **Include / exclude paths** — narrow the crawl with patterns like `/blog/**` or `/api/v2/*`.

Crawls run in the background. Most sites finish in a few minutes; you can keep working while they run.

### Uploading files

Drag and drop one or many PDFs, DOCX files, or Markdown files. Each file becomes its own source with metadata you can manage. Re-uploading the same file replaces the existing version — no duplication.

### Pasted text

For short content — FAQs, plan-specific answers, internal policies — paste it directly. Useful when something isn't in your public docs but you still want the chatbot to know about it.

## Managing sources

Each source shows:

- **Status** — `crawling`, `indexing`, `ready`, or `error`.
- **Pages or sections** — what was discovered.
- **Last indexed** — for re-crawling stale content.
- **Publish status** — `draft` or `published` (see below).

You can re-crawl, archive, or delete a source any time. Deleting removes its contribution to chatbot answers immediately.

## How retrieval works (the short version)

Behind the scenes, HelpAlive reads your sources and indexes them so the chatbot can find the right passage in milliseconds. Whether your user phrases their question like your docs or in their own words, the chatbot finds the closest match and grounds the answer in it.

You don't need to think about this — just keep your sources up to date.

## Draft and publish

Knowledge sources go through the same draft / publish workflow as everything else in the chatbot. New or changed sources stay in **draft** until you publish them — meaning they won't appear in production answers, even though you can preview them on the dashboard's Test page.

The Test page intentionally uses your **draft** content so you can verify that a new source improves answers before shipping. See [Draft & publish](/chatbot/draft-publish) for the full workflow.

## Quality monitoring

The dashboard's **coverage-gaps inbox** flags every question the chatbot couldn't answer well — usually because something is missing from the knowledge base. Topics are grouped, ranked by how often they come up, and surfaced so you know what to write next.

See [Coverage gaps](/analytics/coverage-gaps) for the workflow.

## What's never indexed

- **Private data behind login** — the crawler only follows publicly accessible URLs unless you upload private content directly as files.
- **Drafts you haven't published** — draft sources never appear in production answers.
- **Customer data from your end users** — events and conversations are stored separately from knowledge.

---
title: "Configure guidance triggers and audience targeting"
description: "Set up where and when HelpAlive shows guidance: automatic crowd-intelligence triggers, route and segment targeting, and manual programmatic walkthroughs."
---

HelpAlive gives you layered control over when guidance appears and who sees it. At the base layer, the crowd intelligence engine fires guidance automatically when it detects a user deviating from successful paths — no setup required. On top of that, you can restrict guidance to specific pages, target it to particular user segments, or trigger walkthroughs programmatically from your own code. All targeting configuration lives in the HelpAlive dashboard.

## Automatic triggers

HelpAlive's crowd intelligence engine observes session behavior across all your users and learns what a successful path looks like for each flow in your product. When a user's behavior diverges from that pattern — hesitating, backtracking, or stalling — HelpAlive fires the most relevant guidance automatically.

You do not need to tag events or write any code for automatic triggers to work. Installing the script and calling `identify()` is enough.

## Targeting configuration

### Route and page targeting

By default, HelpAlive monitors all pages in your product. You can narrow a walkthrough to specific routes so guidance only appears in the right context.

In the dashboard, route patterns use glob-style matching:

| Pattern | Matches |
|---|---|
| `/onboarding/*` | All paths under `/onboarding/` |
| `/dashboard` | Exact match only |
| `/projects/*/settings` | Settings page for any project |

<Note>
Route targeting applies per walkthrough. Each walkthrough can have its own set of allowed routes, so you can have a different guide for onboarding than for feature discovery.
</Note>

### User segment targeting

You can restrict a walkthrough to users who match specific trait conditions. Segment rules are evaluated against the traits you pass in `identify()`.

Examples of segment rules:
- `plan = 'pro'` — show only to Pro plan users
- `createdAt < 30 days ago` — show only to users who signed up in the last 30 days
- `role = 'admin'` — show only to admin users

You can combine multiple conditions with AND / OR logic in the dashboard rule builder.

### Setting up targeting in the dashboard

<Steps>
  <Step title="Open the walkthrough you want to target">
    In the HelpAlive dashboard, go to **Walkthroughs** and select the walkthrough you want to configure. Click **Targeting** in the walkthrough editor.
  </Step>
  <Step title="Add route rules">
    Under **Page targeting**, enter the URL patterns where this walkthrough is allowed to appear. Leave the field empty to allow the walkthrough on all routes.
  </Step>
  <Step title="Add segment rules">
    Under **User targeting**, click **Add rule** and select a trait from the dropdown. Set the operator and value. Add additional rules as needed and choose whether they should all match (AND) or any should match (OR).
  </Step>
  <Step title="Save and review">
    Click **Save targeting**. The walkthrough will now only fire when both the route and segment conditions are satisfied. You can preview which users would qualify using the **Audience preview** panel on the right.
  </Step>
</Steps>

## Manual triggers

You can trigger a specific walkthrough programmatically — for example, from a help button, an empty state, or a feature announcement banner.

```javascript
window.HelpAlive.showWalkthrough('walkthrough-id');
```

Replace `'walkthrough-id'` with the ID shown in the dashboard under **Walkthroughs → Settings** for the walkthrough you want to trigger. Manual triggers bypass automatic trigger logic but still respect frequency controls and dismiss state.

<Tip>
Manual triggers are useful for onboarding checklists, contextual help buttons, or "show me how" links — anywhere users explicitly ask for guidance. Pair them with automatic triggers so users who don't ask still get help when they need it.
</Tip>

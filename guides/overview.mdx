Guides are interactive, in-product walkthroughs — multi-step flows that lead a user through a task, attached to real elements in your product. They reuse the SDK's page-context awareness and feed execution events back into the analytics pipeline so you can measure what they actually move.

<Note>
  **Status today.** The guide engine **runtime** is shipped and battle-tested: resolver, spotlight overlay, state machine, lifecycle events, and a 40 KB lazy-loaded bundle. The dashboard guide editor (record-mode authoring, draft / publish UI) is in active development. Until that ships, custom guides for early-access customers are authored directly by HelpAlive.
</Note>

## How guides will work end-to-end

1. **Author** — click through your product in record mode, or define steps in the editor.
2. **Stage** — guides go into draft until published, atomically.
3. **Target** — segment by tenant, role, plan, or page. Per-tenant exclusions are first-class.
4. **Trigger** — programmatically with `HelpAlive.startGuide(...)`, or (soon) when the chatbot resolves a goal that matches a published guide.
5. **Run** — the SDK lazy-loads the engine, the resolver matches each step's fingerprint to a live DOM element, and the spotlight overlay advances on click or step advancement.
6. **Measure** — every step emits a lifecycle event. Completion rates, drop-off steps, and friction inside guides flow back into the analytics tables.

## SDK methods available today

```typescript
// Start a guide
HelpAlive.startGuide(guide, options?: { bundleUrl?: string; loadTimeoutMs?: number });

// Stop the active guide
HelpAlive.cancelGuide();

// Preload the engine bundle (call on chatbot boot for sub-second start)
HelpAlive.preloadGuides({ ids: string[] });

// Read the current controller
HelpAlive.getActiveGuideController();

// Subscribe to guide-start events
HelpAlive.onGuideStarted((event) => { ... });
```

See the [SDK API reference](/sdk/api-reference) for full signatures.

## Per-tenant exclusions

Some guides shouldn't run for some tenants — for example, an enterprise customer running a custom workflow won't want generic onboarding nudges. Exclusions are configurable per guide per tenant from the backend; the editor UI will expose them when it ships.

## Looking further out

The longer-term vision is for the chatbot to **plan** a multi-step task and the guide engine to **execute** the steps in real time — turning a user's question ("how do I migrate my workspace?") directly into a running guide. The runtime pieces of that picture are in place; the planning side depends on better behavior-to-flow mapping and a deeper integration we haven't built yet.

We mark this as future work because we want to be precise about what ships today versus what we're building next.

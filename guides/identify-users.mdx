---
title: "Identify your users and enable personalized guidance"
description: "Learn how to call identify() to tie sessions to real users, enabling personalized guidance, accurate analytics, and user-level insights in the dashboard."
---

Calling `identify()` tells HelpAlive who is using your product. Without it, HelpAlive can still detect friction and show guidance, but every session is treated as anonymous. Once you identify a user, HelpAlive can personalize guidance to their plan or account age, attribute session insights to specific users in the dashboard, and apply per-user frequency controls so the same person never sees the same walkthrough twice in quick succession.

## The identify call

Call `window.HelpAlive.identify()` after a user authenticates — on login, after a session is restored from a cookie, or whenever user context first becomes available.

```javascript
window.HelpAlive.identify('user_123', {
  name: 'Jane Smith',
  email: 'jane@example.com',
  plan: 'premium',
  createdAt: '2026-01-15T00:00:00Z'
});
```

The first argument is the user ID. The second argument is a traits object containing any properties you want HelpAlive to know about this user.

## When to call identify

Call `identify()` as early as possible after authentication — ideally before the user's first page view in the authenticated app. Placing the call in your post-login handler or inside your app's bootstrap sequence ensures HelpAlive has user context for the entire session.

<Note>
If your app uses single-page routing, you only need to call `identify()` once per session. HelpAlive persists the identity across route changes automatically.
</Note>

## Required and optional parameters

<Tabs>
  <Tab title="Required">
    **userId** — a string that uniquely identifies the user in your system. This can be a database ID, UUID, or any stable identifier. It must be consistent across sessions so HelpAlive can build an accurate picture of each user over time.
  </Tab>
  <Tab title="Optional traits">
    All properties in the traits object are optional, but the following are recognised by HelpAlive and unlock specific features:

    | Trait | Type | Description |
    |---|---|---|
    | `name` | string | Display name shown in dashboard session views |
    | `email` | string | Associates sessions with a user record |
    | `plan` | string | Enables plan-based targeting for walkthroughs |
    | `createdAt` | ISO 8601 string | Used to target new users (e.g., account age < 30 days) |
  </Tab>
</Tabs>

## Custom traits

You can pass any additional key/value pairs alongside the standard traits. HelpAlive stores them and makes them available for targeting rules in the dashboard.

```javascript
window.HelpAlive.identify('user_123', {
  name: 'Jane Smith',
  email: 'jane@example.com',
  plan: 'premium',
  createdAt: '2026-01-15T00:00:00Z',
  role: 'admin',
  teamSize: 12,
  industry: 'fintech'
});
```

Custom traits follow the same targeting rules as standard traits. For example, you could configure a walkthrough to appear only when `role === 'admin'` or `teamSize > 10`.

## Anonymous users

HelpAlive works without `identify()`. The crowd intelligence engine observes sessions regardless of whether a user is identified, and guidance will still trigger when deviation from successful paths is detected. The difference is that anonymous sessions cannot be filtered or segmented in the dashboard, and per-user cooldowns are tracked by browser session rather than by user ID.

If your product has both public and authenticated areas, you can call `identify()` only in the authenticated sections and leave the rest anonymous.

<Warning>
Do not pass sensitive data in the traits object. This includes passwords, payment card numbers, bank account details, social security numbers, or any other credentials. Traits are used for targeting and display only — store sensitive data in your own systems.
</Warning>

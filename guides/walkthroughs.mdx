---
title: "Create guided in-product walkthroughs step-by-step"
description: "Build step-by-step guided flows that appear inside your product, pointing users at specific UI elements exactly when they need help completing a task."
---

Walkthroughs are step-by-step guided flows that appear directly inside your product. Each step highlights a specific UI element — a button, form field, menu item, or any other element on the page — and displays a small overlay with a title, body text, and an optional call-to-action button. HelpAlive advances the walkthrough as the user interacts with your product, making the experience feel native rather than like a separate tutorial layer.

You create and manage walkthroughs entirely in the HelpAlive dashboard. No code changes are needed once the script is installed.

## Creating a walkthrough

<Steps>
  <Step title="Open Walkthroughs and create a new walkthrough">
    In the HelpAlive dashboard, navigate to **Walkthroughs** in the sidebar. Click **New Walkthrough**. Give your walkthrough a descriptive internal name — this name is only visible to your team in the dashboard, not to users.
  </Step>
  <Step title="Set the entry URL">
    Enter the URL where the walkthrough begins. HelpAlive will only initiate this walkthrough when the user is on a page that matches the entry URL. You can use an exact path or a glob pattern such as `/onboarding/*`.
  </Step>
  <Step title="Add steps">
    Click **Add step** to build out your walkthrough. For each step, configure:

    - **Target element** — the UI element this step points at. Click **Pick element** to use the visual selector, which opens your product in a preview frame and lets you click the element directly. Alternatively, enter a CSS selector manually.
    - **Title** — a short, descriptive heading for the step overlay.
    - **Body** — the instruction or explanation shown to the user.
    - **CTA button** (optional) — a button label and action. The action can advance to the next step, open a URL, or dismiss the walkthrough.

    Repeat until you have all the steps your flow requires.
  </Step>
  <Step title="Set the trigger">
    Choose how the walkthrough starts:

    - **Automatic** — HelpAlive's crowd intelligence engine fires the walkthrough when it detects the user is struggling in the relevant flow. No additional setup needed.
    - **Manual** — the walkthrough only starts when triggered programmatically via `window.HelpAlive.showWalkthrough('walkthrough-id')`. Use this for help buttons or onboarding checklists.

    You can enable both options simultaneously so the walkthrough fires automatically for users who struggle and is also available on demand for users who ask.
  </Step>
  <Step title="Publish and test">
    Click **Publish** to make the walkthrough live. Before enabling automatic triggers for all users, use **Test mode** to walk through the experience yourself. In test mode, the walkthrough fires for your session only, regardless of the trigger configuration, so you can verify each step targets the right element and the copy is clear.

    Once you are satisfied, enable automatic triggers and monitor completion rates in the **Insights** tab.
  </Step>
</Steps>

## Step configuration reference

Each step in a walkthrough has the following fields:

| Field | Required | Description |
|---|---|---|
| Target element | Yes | CSS selector or auto-detected element the overlay points at |
| Title | Yes | Short heading displayed in the step overlay |
| Body | Yes | Instruction or explanation text |
| CTA button label | No | Label for the primary action button |
| CTA button action | No | Advance, open URL, or dismiss |

## Best practices

Following these practices leads to higher walkthrough completion rates and better user outcomes.

**Keep each step focused on one action.** If a step asks the user to do two things, split it into two steps. Users are more likely to complete a walkthrough when each step is immediate and unambiguous.

**Use clear, imperative language.** Write step copy as direct instructions: "Click **Save** to continue", "Enter your team name here", "Select a plan to proceed." Avoid passive constructions or explanatory prose — users in the middle of a task want to act, not read.

**Use the visual selector rather than writing CSS selectors by hand.** Auto-detected selectors are more resilient to markup changes than manually written selectors, and the visual selector lets you confirm the right element is targeted before publishing.

**Test on real users before enabling automatic triggers.** Publish in manual-trigger mode first and share the walkthrough with a small group of users or teammates. Gather feedback on clarity and pacing, then switch to automatic triggers once the flow feels right.

**Monitor the Insights tab after launch.** The dashboard shows per-step drop-off rates. If users are consistently abandoning at a particular step, revisit the copy or the target element for that step.
